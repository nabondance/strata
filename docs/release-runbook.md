# First npm release handoff

As of 2026-10-08, `context-strata@0.1.0` is a release candidate, not a published package. The package name returned `{"error":"Not found"}` from `https://registry.npmjs.org/context-strata` in a browser on this date; availability can change until publication. `npm whoami` returned `ENEEDAUTH`, so the first publication is blocked on npm authentication. Do not put an npm token in this repository or `question.md`.

The candidate has passed `pnpm typecheck`, `pnpm test`, `pnpm pack`, and installation of the tarball in a clean directory. That install exercised the CLI with a named OpenAI model and the `diff` command. GitHub CI on Node 22 and 24 passed for commit `970d78e` ([run](https://github.com/nabondance/strata/actions/runs/37746079122)). A read-only Claudes smoke check processed 89 revisions in the encoding mode and compared two commits with `strata diff`. The composite PR Action ran successfully through the [manual smoke workflow](https://github.com/nabondance/strata/actions/runs/37747127783) on commit `77ff447`, and its job summary contained the expected model-labeled delta. It has not yet been used by a separate repository.

The maintainer chose CI publishing. Use [npm trusted publishing](https://docs.npmjs.com/trusted-publishers/) with GitHub Actions and OIDC for routine releases. A publish workflow should run on GitHub-hosted runners, use Node 24 with npm 11.5.1 or later, grant `id-token: write` only to the publish job, and verify the package before `npm publish`. Configure npm to trust the exact `nabondance/strata` workflow filename after the package exists; no long-lived publish token is needed in that workflow. The package's `repository.url` must match the GitHub repository. Limit tag or environment access so routine pushes cannot publish.

The first release is a bootstrap: [npm's trust command requires an existing package](https://docs.npmjs.com/cli/v11/commands/npm-trust/#prerequisites), so CI OIDC cannot yet claim the unregistered name. Once the maintainer has authenticated to npm with 2FA, recheck the package name, rerun project checks and the tarball install, publish `0.1.0` with public access, and verify `npm view context-strata@0.1.0` and `npx context-strata@0.1.0 --version` from a clean directory. Then configure the trusted publisher for the future CI workflow, update the README's unpublished wording, and tag the tested release commit as `v0.1.0`. If the name is taken first, choose another package name and repeat package and CLI checks. Do not trigger a release workflow or publish a package until its exact artifact and version are reviewed. The publish task stays in progress until these checks pass.
