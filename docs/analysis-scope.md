# Current analysis scope

Strata reads Git-tracked files from every commit on the selected branch's first-parent path, oldest to newest. It does not inspect untracked or ignored files, global user configuration, or the working tree's current contents. A shallow clone is labeled incomplete.

## Recognized paths

These are inventory rules, not claims that an agent loaded a file in a session. `**/` means the pattern also applies under a nested project directory.

| Path pattern | Provider | Category | Measurement |
| --- | --- | --- | --- |
| `**/CLAUDE.md`, `**/CLAUDE.local.md`, `**/.claude/CLAUDE.md` | Claude | instructions | estimated stored-text tokens |
| `**/AGENTS.md` | shared (Claude, Codex; Gemini CLI when configured) | instructions | estimated stored-text tokens |
| `**/AGENTS.override.md` | Codex | instructions | estimated stored-text tokens |
| `**/.claude/skills/<name>/SKILL.md` | Claude | skills | estimated stored-text tokens |
| `**/.agents/skills/<name>/SKILL.md` | shared (Codex, Gemini CLI) | skills | estimated stored-text tokens |
| Other tracked files under either skill directory | same provider as the skill | skills | source bytes only |
| `**/.claude/agents/**/*.md` | Claude | agents | estimated stored-text tokens |
| `**/.claude/rules/**/*.md` | Claude | rules | estimated stored-text tokens |
| `**/.claude/commands/**/*.md` | Claude | commands | estimated stored-text tokens |
| `**/.claude/agent-memory[-local]/<name>/**/*.md` | Claude | memory | estimated stored-text tokens |
| `**/.claude/settings.json`, `**/.claude/settings.local.json` | Claude | settings | source bytes only |
| `.mcp.json` at repository root | Claude | tools | source bytes only |
| `**/.codex/config.toml` | Codex | settings | source bytes only |
| `**/.codex/agents/*.toml` | Codex | agents | source bytes only |
| `**/.codex/rules/**/*.rules` | Codex | rules | source bytes only |
| `**/GEMINI.md` | Gemini CLI (unless `context.fileName` leaves it out) | instructions | estimated stored-text tokens |
| `**/.gemini/system.md` | Gemini CLI | instructions (conditional system-prompt override) | estimated stored-text tokens |
| `**/.gemini/agents/*.md`, except names starting with `_` | Gemini CLI | agents | estimated stored-text tokens |
| `**/.gemini/skills/<name>/SKILL.md`, `**/.gemini/skills/SKILL.md`, `**/.agents/skills/SKILL.md` | Gemini CLI | skills | estimated stored-text tokens |
| Other tracked files under `.gemini/skills/<name>/` | Gemini CLI | skills | source bytes only |
| `**/.gemini/settings.json` | Gemini CLI | settings | source bytes only |
| `**/.gemini/commands/**/*.toml` | Gemini CLI | commands | source bytes only |

Other `.md`, `.json`, `.toml`, and `.rules` files under `.claude/`, `.codex/`, or `.agents/` remain visible as `other` with source bytes only. Tracked skill references, scripts, and assets of any extension are grouped with their skill directory as source-only resources; a resource-only directory is not treated as a valid skill manifest. `.agents/` files outside a recognized skill directory have provider `unknown`. Gemini CLI skips `.gemini/agents` files whose names start with `_` and does not read subdirectories there, so those files stay visible as source-only `other`. Files outside these conventions are not inferred to be agent configuration. Git symlinks are skipped. A shared component lists in `readers` the providers documented as reading its path; a reader can still depend on a runtime condition Strata does not resolve. `AGENTS.md` is marked shared because both [Codex](https://learn.chatgpt.com/docs/agent-configuration/agents-md) and, conditionally, [Claude Code](https://code.claude.com/docs/en/memory) can read it. Claude's default may prefer `CLAUDE.md`; Codex overrides may supersede `AGENTS.md`. Strata does not resolve those runtime conditions. Gemini CLI reads `AGENTS.md` only when its settings name it in `context.fileName`; Strata resolves that one condition per revision, as described below. `.agents/skills` is shared between Codex and Gemini CLI, which both discover project skills there; Claude Code does not.

The recognition rules follow current provider documentation for [Claude instructions and rules](https://code.claude.com/docs/en/memory), [Claude skills and commands](https://code.claude.com/docs/en/skills), [Claude subagents and memory](https://code.claude.com/docs/en/sub-agents), [Claude settings](https://code.claude.com/docs/en/settings), [Claude MCP](https://code.claude.com/docs/en/mcp), [Codex instructions](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [Codex skills](https://learn.chatgpt.com/docs/build-skills), [Codex custom agents](https://learn.chatgpt.com/docs/agent-configuration/subagents), [Codex project configuration](https://learn.chatgpt.com/docs/config-file/config-basic), [Codex rules](https://learn.chatgpt.com/docs/agent-configuration/rules), and Gemini CLI's [context files](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/gemini-md.md), [configuration](https://github.com/google-gemini/gemini-cli/blob/main/docs/reference/configuration.md), [agents](https://github.com/google-gemini/gemini-cli/blob/main/docs/core/subagents.md), [skills](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/using-agent-skills.md), and [custom commands](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/custom-commands.md). Gemini's default context filename is `GEMINI.md`. A configured `context.fileName` replaces that default. At each revision Strata reads the tracked repository-root `.gemini/settings.json`, ignoring `//` and `/* */` comments as Gemini CLI does. When `context.fileName` (or its older name, `contextFileName`) is set, the revision's `geminiContextFiles` records which of `AGENTS.md` (`agents-md`) and `GEMINI.md` (`gemini-md`) it names; the Gemini view and Gemini provider totals for that revision include exactly those context files, at any depth. Without that setting only `GEMINI.md` is included. `AGENTS.md` and `GEMINI.md` components carry the matching `contextFile` label, so the decision does not depend on paths and survives `--shareable`. Other configured names are neither resolved nor stored. Settings that do not parse, nested `.gemini/settings.json` files, and user and system settings outside the repository are not resolved either. A `GEMINI.md` left out by the settings stays labeled Gemini and counted once in All files. `.gemini/system.md` is only used when `GEMINI_SYSTEM_MD` selects it. Gemini CLI also discovers project skills from `.agents/skills`, giving them precedence over `.gemini/skills`; those files are stored once as shared components read by Codex and Gemini CLI. A skill with the same name in both directories appears twice in the Gemini view, because Strata does not resolve that precedence. Gemini CLI also accepts a single `SKILL.md` directly in either skill directory; Strata records it as a Gemini skill rooted at that directory, but other files beside it are grouped by their own subdirectory, as manifest-less bundles, because path classification cannot see the sibling manifest. These path labels identify candidates and do not assert runtime loading. Recognition is intentionally conservative: structured Codex and Gemini commands/configuration files remain source-only instead of counting their full source as prompt text.

## Measurements and history

The default token figure is a **comparison estimate**: `ceil(UTF-8 byte length / 4)` for each recognized instructional file, summed across files. The same method is applied to every revision. It is neither an Anthropic nor OpenAI tokenizer. Optional `--tokenizer openai-cl100k_base` and `openai-o200k_base` modes use local `js-tiktoken@1.0.21` for encoding-exact counts of valid UTF-8 instructional text. `--model` maps a small supported set of OpenAI model names to those encodings and records the selected name; unknown names fail. The selected encoding applies to every instructional file, independent of its provider label, so historical totals remain comparable. Invalid UTF-8 instructional blobs fail in an encoding mode instead of silently producing an inexact count. `--precise` is a separate, explicit opt-in for `strata analyze`: it picks, per provider, a signed-in provider CLI account, then an API key, then a local exact tokenizer, then the estimate (see [the decision record](decisions.md#measurement)), sends only recognized instructional text to [Anthropic's Messages count endpoint](https://platform.claude.com/docs/en/api/messages/count_tokens), [Gemini's countTokens endpoint](https://ai.google.dev/api/tokens), or Vertex AI's count endpoints, and labels returned counts by provider, model, method, implementation/API version, accuracy, credential source, and receiving host. The deprecated `--provider-api` requires named models and both API keys. Shared instruction candidates receive a separate count for each selected provider in their `readers`; heterogeneous counts are not added. A Gemini context file version is sent to Gemini only when it is present in some revision whose settings make Gemini read it, and its count joins the Gemini total, and appears in the report's Gemini column, only in such revisions. An optional `--codex-model` adds a local OpenAI encoding count for Codex files. API counts exclude the endpoint's one-message wrapper, measured per model, and describe stored text, not actual loaded context or billing. `strata diff --precise` uses the same methods for its two commits. The default and local tokenizer modes never send repository content.

Structured configuration, MCP, permission rules, and supporting files are inventoried by source bytes and excluded from instructional token totals. Category counts describe stored files, not active skills, loaded rules, or runtime cost. Category totals include a `sourceOnlyCount` so a zero token total is not mistaken for an empty source file. Schema version 11 stores each distinct file version once in a top-level `components` list and each revision as its totals plus `changes`. It includes `readers` on shared components, `contextFile` on `AGENTS.md` and `GEMINI.md`, `geminiContextFiles` on revisions whose Gemini settings configure context files, provider token counts and separate per-provider revision totals when API mode is selected, alongside the `skill` root and role on each skill component, a report `privacy.mode`, `credential`, `recipient`, and `fallbacks` on provider measurements, and structured `measurement` fields (`family`, `accuracy`, `encoding`, `model`, `implementation`). The legacy `estimatedTokens` field remains the default comparison estimate in provider API mode; provider counts are separate and never combined into a heterogeneous total. Skill-bundle summaries are derived from the same components already counted by category and must not be added to category totals.

Changes compare adjacent first-parent revisions. Git rename detection (`-M`) supports a rename label when Git finds sufficient content similarity; otherwise the report shows a removal and addition. A merge is compared with its first parent. The report does not infer a refactor or architecture dependency from paths alone.

The HTML comparison view can compare any two sampled revisions, including earlier targets. Its provider, category, and component deltas use the stored measurements at each endpoint. Component identity is provider, category, and path, so an arbitrary-range move can appear as a removal and addition even when an adjacent revision's `changes` array labels a Git-detected rename.

The SVG image contains only the repository and branch names, dates, category labels, and totals; with `--minimal` it contains only the layer shapes and, in its accessible description, the latest totals. The default HTML and JSON contain full commit IDs, dates, paths, provider and category labels, blob IDs, byte sizes, and estimates. They contain no file contents. Provider API mode transfers recognized instruction text to the named services during analysis; `--shareable` changes report identifiers but does not change that transfer. `--shareable` replaces the repository and branch names, commit IDs, paths, skill roots, and blob IDs with deterministic aliases while retaining dates and measurements. These values can still reveal the shape and timing of a project; inspect reports before distribution. Use `--output` to choose where the report is written; Strata does not write to the repository it analyzes unless that path is chosen explicitly.
